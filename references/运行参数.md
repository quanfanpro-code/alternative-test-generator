# 运行参数（由AI填写，用户无需操作）

## 输入识别

AI读取原资料和上下文后生成以下参数。列映射使用**实际表头文字**；多个工作表或表头不在第1行时AI自行检查并填写sheet、header_row。不要要求用户手工维护JSON或提供绝对路径。

{
  "project_name": "实际项目名称",
  "period_start": "2025-01-01",
  "period_end": "2025-12-31",
  "entity_ids": ["E1"],
  "entity_names": {"E1": "资料中的被审计单位实际全称"},
  "normal_balance": "credit",
  "inputs": [
    {
      "role": "balance",
      "path": "实际余额表路径",
      "sheet": "实际工作表名称",
      "header_row": 1,
      "entity_id": "E1",
      "account_name": "应付账款",
      "columns": {
        "counterparty_col": "供应商名称",
        "opening_balance_col": "期初余额",
        "ending_balance_col": "期末余额"
      }
    },
    {
      "role": "journal",
      "path": "实际序时账路径",
      "sheet": "实际工作表名称",
      "header_row": 1,
      "entity_id": "E1",
      "ledger_id": "实际账套标识",
      "columns": {
        "date_col": "日期",
        "voucher_type_col": "凭证种类",

## 字段与约束

- `normal_balance`：credit使用负债方模板；debit使用资产方模板。不同方向分开运行。不同单位的科目也分别识别，不能串账。
- `entity_names`：实际名称，必须覆盖本次entity_ids。被测试往来单位名称来自余额清单，而非这个字段。
- `inputs`：可放多份、多年账簿。同一输入必须已成功inspect，且哈希一致。多工作表明确使用sheet。header_row可指定任意有效行。CSV工作表名为csv_default，单表文件可省略sheet。
- `account_col`是被测试分录的实际科目；不要把整份全科目账簿强行都配置成应付/应收。只有来源本身明确为单科目时才在输入层指定account_name。对方科目缺列时可从完整凭证的反方向分录推导，有多个科目如实并列并保留来源。
- `entity_col`、`ledger_col`、`account_code_col`可按实际映射。单位列可以是内部ID或实际全称；与输入级entity_id矛盾会报错。同名往来单位按被审计单位和测试科目隔离。
- `line_offset`：不同分表的来源行号发生真实标识冲突时可由AI自动确定不重叠的偏移量。重叠导出不能简单重复计入，先核实来源和分录再决定处理。
- `prepared_by`、`reviewed_by`、`prepared_date`、`reviewed_date`、`index_number`、`index_numbers`、`currency`：有事实依据才填。index_numbers以准备结果中的CP编号为键。人员和日期不默认猜测。
- 期初余额缺失不影响候选生成，余额勾稽状态为NOT_RUN；不能把缺失当0。借贷金额都空、非有限数值或不可读公式金额会报具体来源。
- `rules`支持signed_amount、absolute_amount、posting_date、voucher_key、movement_kind；比较支持gte、lte、between、equals、in。movement_kind为increase/decrease。between值为两个数字字符串或两个ISO日期。只有实际获授权的规则才设置user_confirmed=true，不擅自定抽样门槛。
- `selected_line_ids`可直接指定准备结果里的凭证明细ID，显式空列表表示未抽中任何当期凭证；不能回退成全选。无规则且没有指定ID时为完整候选总体。
- `confirmed_decisions`：AI能够根据真实来源查清的别名可写匹配决定，字段为decision_id、journal_line_id、counterparty_id、original_text（真实核实依据）。不能跨单位、跨科目、指向不存在行或伪造用户确认；AI核实的依据应明确写“AI依据……核实”。无法查清时才汇总询问。

## 期后检索

可配置`post_period_end`；默认到提供数据中的最晚日期，实际范围写入准备和生成结果。只检索测试时点之后、同单位同科目的记录。负债方查借方付款候选，资产方查贷方收款候选，资金科目及摘要线索另外判断。非资金重分类或抵销排除；线索不足的行留在post-query.json中，不能当收付款。

`post_rules`可独立控制期后候选筛选，语法同rules；没有期后规则时保留所有符合线索的候选，不沿用当期抽样门槛。期后列示仍不能证明款项对应测试时点余额。

## 主题与验证

支持default、deep-navy、jade、slate、burgundy、coral、sakura、warm-sun、lavender、matcha、peach、misty；默认deep-navy。配色参考excel-master并保存在本技能，不依赖其他技能路径。

generate实际生成xlsx、validation.json、run-manifest.json。validate既可检查运行目录（包含哈希核对），也可检查单个xlsx（内容和公式核对）。校验XML声明与内部引用关系、实际源值与金额、抽取行数、小计和比例公式范围、单位信息和空检查栏。成功才返回0；错误返回2/3/4/5等非零码。

公式保存为可编辑的Excel公式，并设置打开时全量重算。程序独立复核金额及公式范围，不将其宣传为已经在Excel计算引擎重算。成品有意被用户编辑后，原运行目录哈希会变化；此时可单独验证xlsx，不能静默改运行记录为“仍未变动”。
